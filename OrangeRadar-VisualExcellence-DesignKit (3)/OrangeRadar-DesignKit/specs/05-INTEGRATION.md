# Engineering integration / tool choices

Inspect existing route, Razor view, DTOs, JS modules and CSS, visual action registry, auth, speech endpoints, reporting/tests before changing. Reuse services, preserve request antiforgery and policy gates; do not bypass middleware. Keep reusable scoped namespace such as `.orange-radar` after checking existing names. Prefer progressive refactor, not wholesale replacement. JS can be modular in current build strategy, no new bundler mandatory. Existing vendor libraries remain local and pinned. Do not hardcode model paths, usernames, branch, demo values or credentials. No downloads unless needed and approved under environment permissions. If Claude uses MCP/Playwright or existing browser tooling, use only installed/authorized capability, no mandatory MCP setup; read local screenshot paths. Optional starter code is educational, adapt or ignore instead of creating parallel architecture.

## Shared state proposal
A single page state (in memory, use existing architecture): `{ scopeVersion, filters, semanticView, selectedSupplierIds, selectedGroupId, selectedEdgeId, selectedFindingId, activeSection, camera, replay, scenarioIds, pinnedEvidenceIds, currentTurnId, voiceState }`. All controls, charts and AI actions dispatch to same state handlers. Preserve stable graph IDs. Fetch data once per scope; filter/selection locally where access rules permit. On scope update cancel stale fetches, recalculate selection validity, reconcile available records, avoid stale AI commands. Separate filter semantics from graph layout and from permission scope. API remains authoritative. Use AbortController/cancellation tokens on fetch/stream wherever existing. Chart/table and graph counts must agree; exact round-level dedupe.

## Persistence boundary
Session-only state and optionally non-sensitive display prefs (theme, collapsed state, selected semantic view) may be saved; do not put names, supplier IDs, findings, transcripts, prices, record identifiers or raw audio into persistent browser storage on shared devices. Optional server-side saved sessions require explicit scope, user ownership/authorization, expiry, audit and revalidation on restore; no new migration in this visual pass. Pinned report findings may leverage existing in-memory report inputs. Clearly say if save/resume beyond current page is not implemented. Reopening must revalidate authorization and not replay stale actions automatically.

## Libraries and implementation
Cytoscape core layouts/classes/animation and graph algorithms first; optional fCoSE/other extension only if justified. ECharts update transitions and accessible HTML table. CSS/SVG and Web Audio for motion/voice; no fake visualization. Local existing Playwright or browser harness for capture. Use test fixture as isolated synthetic unit data only, never production rendering. Keep reports and actual bid seal policy intact. Review new dependencies license, pinned version and local/offline support. Keep project documentation updated with layout behavior and limits.
