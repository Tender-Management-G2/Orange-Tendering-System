# Live AI voice — design and interaction contract

Keep existing local pipeline (Qwen 3.5 4B, Whisper Small, persistent Piper). The task is user experience and visual orchestration, not another AI stack. Compact dock shares exact session state with expanded voice workspace. State machine: idle → permission/listening → transcribing → analyzing → speaking → listening; muted/interrupted/error/ended explicitly handled. Current status derived from actual events, not animation timing. Display locale, readiness, transcript, concise tool status with actual completion. State labels readable independently of color.

## Audio visual signature
Use an understated orb with two or three discrete rings, clean waveform across a dedicated conversation surface, real mic RMS/envelope when listening, real playback signal when speaking. Drive with Web Audio `AnalyserNode` (time-domain samples), use smoothing/normalization, no random audio simulation. For playback connect analyzer to actual audio output route once; do not double-route audio or attach new MediaElementAudioSourceNode repeatedly. If analysis signal unavailable, show simple state icon rather than fake waveform. No artificial confidence meters or unmeasured latency. Use requestAnimationFrame only while visible and active, dispose on end. Reduced motion shows level meter/text. Use Web Audio only after gesture/resume. Do not create a second recording stream for visual effects; consume existing stream. Never start mic automatically on page load.

## Conversation UX
One session across all sections, compact dock with start/mute/stop/end and expand; dedicated workspace with transcript, input, language selector (Auto/AR/EN), speed, voice toggle, context chips, suggested questions, action and evidence links. Transcript keeps `dir=auto`, Arabic/English fonts legible, explicit user vs assistant labels, timestamps if useful, copy accessible. No duplicate chat widget overlay or unmanaged listeners. Avoid auto-scroll when reading older turns. Voice controls have labeled buttons, focus, keyboard and permission-denied fallback. End session: stop media tracks, cancel recognition/generation/speech/visual queues, abort pending requests, close context when appropriate, clear timers/RAF. Preserve current selection and text fallback. Explicit Stop must remain reliable; automatic barge-in remains experimental until physical mic/speaker validation. Echo cancellation/noise suppression as supported by browser and existing pipeline; no assumption of perfect full duplex.

## AI-directed actions
Use existing verified data tools and structured client actions, allowlisted aliases mapped to existing application methods. Examples (not mandated endpoint names): setView(category|competition|tender|forensic), setFilters, focusGroup, focusSupplier, selectSuppliers, focusPath, openEvidence, showChart, jumpSection, startReplay/pauseReplay, showScenario, startBriefing, exportReport. Validate all IDs and authorization server-side for data, and validate bounded client args; do not execute model-generated code. Tool response contains action ID, turn ID, data scope/version, valid evidence references. Ignore stale messages after cancellation or scope change. Show action in transcript only when status known. Keep manual and AI UI state unified. Provide option to stop guided camera and don't move viewport while user actively reading unless requested.

## Example acceptance dialogue
“Show all suppliers.” → full market, category view. “Who often competes with Wadi Digital?” → actual competition view and matching evidence, focus only if authorized. “Compare these two.” → use current selection; if ambiguous ask. “Why are they connected?” → actual relationship record(s), explain context not allegations. “Play the timeline.” → actual replay, interruptible. “Brief me.” → real scenes/narration. “Export our findings.” → existing report. “Delete supplier.” → refuse, no mutation tool. If dataset has no links, clearly say so and show all suppliers. See motion spec for camera sequencing.

## Performance and privacy
Use existing pipeline; preserve model warm behavior, no concurrent heavyweight model loading gratuitously. Report cold/warm separately, measured stop-to-first-audio latency; prior ~5s is baseline not a promise. Physical tests Arabic + English, quiet/speaker/headphones, interruption, mic permission denial, navigation and cleanup. No raw audio persistence by default. No external speech/LLM APIs. Do not imply screen reading through vision; send structured page context only. Maintain existing numeric validation and enhance claim evidence presentation without pretending it guarantees truth.
