# Network engine — semantics, layout and interaction specification

## Scope and views
Default **All suppliers / Category**. Supplier universe is authorized registered suppliers in selected scope; show zero-activity and isolated suppliers, distinguish inactive/eligible status via accessible labels. Display counts of visible vs scoped suppliers when filters hide nodes. Small demo/team datasets should show all names by default. Category derived only from stored approved business classification. Uncategorized is explicit. If suppliers have multiple categories, choose existing designated primary category if present; else deterministic primary presentation with multi-category badges and transparent membership; do not duplicate supplier nodes or double-count. Category groups are visual containers, not real organizations. No fake hub. Group containers may be compound nodes in Cytoscape or noninteractive hull overlays; cluster labels are clickable via real controls.

Four semantic views (separate from relationship and layout filters):
| View | Node set | Grouping/layout | Edge semantics |
|---|---|---|---|
| Category | all scoped suppliers | stored category, roomy bounded groups | supported direct supplier relationships only |
| Competition | same suppliers | connected components of recurring shared-round edges; optional real community algorithm only if justified | distinct closed rounds with submitted offers by both, default recurring >=2 configurable, ordinary context never suspicion |
| Tender | suppliers + authorized tender/round entities | bipartite lane layout or tidy graph, stable positions | actual submitted offers per closed round, distinguish rounds; optional awarded edge only verified |
| Forensic | all suppliers available; focus signals by default | evidence-related components, isolated context optionally dimmed | verified detector outputs only, no guilt score |

Competition components are transitive, not every member competes with every other member. Explain method and show singletons. Do not invent stronger links, company ownership, tiers, partnerships, geography, centrality or risk. In all views, graph IDs are stable (supplier:<id>, round:<id>, document:<id>, finding:<id> etc.), server-authorized and names are not identifiers. Keep selection across layouts and clear only if scope excludes it; display reason. Group counts not counted as real supplier nodes. Graph scope includes closed rounds only for bid-based relationships. When replaying, rebuild from records available as of time cursor, including disclosure restrictions.

## Edge/data contract (adapt existing DTOs; no parallel backend)
Node fields: id, type, label, categoryId, categoryLabel, status, activityCount (closed rounds), metrics with numerator/denominator if applicable, related authorized IDs. Edge fields: stable id, sourceId, targetId, type, classification=context|review, sampleSize, weight metric name/value/unit, evidenceIds (opaque authorized references), first/last observed where available, period, method, limitations. Allow multiple types between same pair; distinguish in inspector and parallel edges or expandable bundle. Deduplicate by endpoint pair+type and evidence IDs, never sum overlapping counts as independent events. Contact values masked unless current role explicitly allowed. Never send sealed bids to frontend, chart or AI.

Evidence types: repeated joint participation, normalized shared contact, relative price patterns and price similarities from comparable items/units/currency/rounds, award rotation, exact SHA-256 match, semantic text similarity, repeated submission timing. Existing detectors source of truth. Normal co-participation is context. Exact matches can be legitimate common forms. No unverified evidence, no confidence % as proxy for fraud.

Collapsed category link = aggregate of actual cross-category supplier edges of selected type; label distinct supplier-pair count (and type-specific record metric if available). Never create a relationship just because groups exist. For all types, report distinct pairs and breakdown by type, don't add dissimilar weights. Click aggregate to list underlying edges and expand. If none, no line. Default with small datasets show actual direct edges, not aggregate. Supplier isolated by filter remains visible and labeled unless explicitly hidden.

## Visual grammar
Supplier circular solid icon with modest outline; tender rounded square; document diamond or file icon; contact attribute small hexagon; group boundary translucent colored hull or rounded container. Node color category (stable palette, color not sole cue); border/shape states; selected orange ring; size bounded based on participated closed rounds (e.g. diameter 34–64 css pixels at 1× using sqrt scale and legend), never risk. Ordinary edges muted slate with line style; thickness 1–4 according to count only within same type; review signals amber dashed+legend; semantic similarity purple dashed, exact files distinguish label; selected path orange high contrast. Use restrained glow only for active focus or voice state, no gratuitous particles. Labels off-node with solid contrast halo and collision handling; full names available on hover/focus/table. Use group label+count and coherent spacing. On dense graph label only important nodes until semantic zoom, but for 12–20 names aim to show all. Minimaps must represent actual viewport or omit them.

## Layout strategy
Start with deterministic category anchors and per-group layout (circle/grid or precomputed stable packing); use true Cytoscape preset target positions with animated repositioning, then optional short bounded layout pass where justified. Avoid continuous jitter. Compute/snap positions from current viewport, reserve label space, maintain stable order by ID, cache per view and scope (non-sensitive memory). Competition layout components sorted by size then ID; tender layout two clear columns or grouped lanes, handle cross links; forensic layout components, evidence expands on demand. If existing compound/fCoSE supports it reliably, use after local compatibility check; no mandatory new dependency. Avoid visual-only connector/hub artifacts. Recompute group hulls from current node bounds during transition, not hardcoded image coordinates. Handle resize with ResizeObserver and debounced cy.resize; fit only on explicit action or initial scope; do not reset user camera every filter. Offer zoom, pan, fit, reset, fullscreen, search, relationship/category/date filters, table fallback, export. Provide breadcrumbs and back/reset, pointer/keyboard equivalent controls, touch support. Use pointer events deliberately, accessible HTML inspector/table outside canvas.

## State transitions
- Open: all suppliers visible, group labels, contextual links; inspector collapsed; user can see scope and legend. Reveal only on first load; data ready event controls animation.
- Select group: pan/zoom 350–600ms, expand/spread members, dim unrelated edges/nodes without hiding market; inspector gives members, participation/awards only if factual, pair counts, related rounds, buttons Focus/Compare/Ask AI. Back restores prior viewport and scope.
- Select supplier: keep category context, highlight direct neighbors and links; inspector shows status, category, activity, awards/response and DNA link; expand tender/doc/contact nodes on demand. Double-click or explicit Focus enters ego view; Back restores prior view. Isolated supplier shows clear reason.
- Select edge: highlight endpoints and type, show evidence IDs and human-readable explanation; reveal supporting rounds/documents, click opens existing authorized details. Multiple edges chooser if needed.
- Multi-select: visible chips, compare 2–5 suppliers, apply same selection to charts, AI context and report pins. No mutation. Ctrl/Shift or accessible checkboxes; keyboard equivalents. Clear selection without clearing filters.
- Trace path: two selected nodes, shortest path based only on selected allowed real edge types, no path => honest empty state. Explain each hop; indirect path not proof of direct relation. Effects animate sequentially once.
- Timeline: play/pause/scrub, actual dated records, cancellation on filter or user intervention. Keep consistent node positions where possible. Stop/reduced motion supported.
- AI commands call exact same state transition functions; no duplicate graph instance or independent camera controller. New user turn or manual input cancels pending visual actions; stale results ignored.
